# Audit fonctionnel & correctifs — P2P Fraud Detective FR

**Date :** 2026-06-12 · **Périmètre :** `apps/web` (Next.js 15) déployé sur Vercel + backend FastAPI · **Branche :** `claude/trusting-napier-284f63`

## Objet

Vérifier que tous les modules/outils mis en avant (les ~30 routes du menu §01→§06), les
animations et les outils IA sont réellement fonctionnels, sans bug, erreur, hallucination ni
régression — puis corriger ce qui cloche, de façon tracée.

## Méthodologie

1. **Sweep automatisé** de chaque route (desktop + mobile) via Playwright : erreurs console,
   erreurs page (hydratation), requêtes réseau 4xx/5xx, captures d'écran. Script réutilisable :
   `apps/web/scripts/audit-routes.mjs` (paramétrable par `AUDIT_BASE_URL`).
2. **Trois conditions** comparées : (a) prod Vercel actuelle, (b) build local **sans** backend,
   (c) build local **avec** backend FastAPI démarré (base vide, comme en prod).
3. **Portes qualité** : `typecheck`, `lint`, `vitest`, `next build` (toutes vertes avant/après).

## Synthèse

Le produit est **solide** : **24/30 routes 100 % propres** dès le départ sur la prod, et
**0/30 anomalie** une fois les correctifs appliqués + un backend sain branché. Quatre anomalies
réelles ont été identifiées et corrigées ; deux pistes se sont révélées être des comportements
attendus (faux positifs).

## Correctifs

### F1 — Cohérence du Cockpit
- **`lib/cockpit-payload.ts`** (nouveau) : `isEmptyCockpitKpisPayload()` durci — un payload est « vide »
  si aucune métrique **ni** aucune valeur de tendance n'est positive.
- **`app/api/v1/cockpit/kpis/route.ts`** : utilise le helper extrait.
- **`lib/cockpit-payload.test.ts`** (nouveau) : 5 tests (dont le cas backend-vide réel).
- **Preuve end-to-end** : backend brut `:8000` → `exposure_total_eur: 0` ; frontend proxifié `:3102`
  → **6 579 353 €, 383 cases** (fallback démo). Avant le correctif, les zéros passaient tels quels.

### F2 — Hydratation #418
- **`lib/utils.ts`** : nouveau `formatDateTime()` avec `timeZone: "Europe/Paris"` épinglé (déterministe SSR/CSR).
- **`fraud-case-360-client.tsx`** : remplace les 2 `toLocaleString("fr-FR")` nus par `formatDateTime()`.
- **Preuve** : re-sweep avec serveur `TZ=UTC` + client Europe/Paris (condition exacte de la prod) →
  `/fraud-case-360` **sans erreur page** (#418 éliminé).

### F3 — Favicon
- **`app/icon.svg`** (nouveau, identité crosshair forensic). Next injecte
  `<link rel="icon" type="image/svg+xml" href="/icon.svg">` → les navigateurs n'interrogent plus
  `/favicon.ico` (plus de 404 console). `/icon.svg` → 200 vérifié.

### F4 — Messagerie IA gracieuse (vérification)
- Les **5 panneaux** (`case360-dossier-panel`, `copilot-panel`, `risk-replay-panel`,
  `scenario-narrative-panel`, `rule-studio-panel`) affichent un message « indisponible / backend requis »
  **codé en dur** sur toute erreur ; `lib/api-client.ts` lève sur tout non-2xx → la mutation passe en
  erreur. Vérifié 3 fois : lecture de code, 404 live (Copilote « indisponible » visible), **503 backend réel**
  (`POST /rules/draft` → *« ANTHROPIC_API_KEY manquante »*). Aucun correctif nécessaire.

### F5 — Accessibilité animations
- **`forensic.css`** : bloc `@media (prefers-reduced-motion: reduce)` (scopé `.forensic`) — animations
  décoratives neutralisées, ticker figé à sa position de départ.
- **Preuve** : `reduce` → ticker `animation-name: none` ; `no-preference` → `tickerScroll 60s`
  (expérience par défaut **inchangée**).

## Recommandation déploiement (hors code)

C1 et C3 ont une **cause commune** : la prod Vercel a `NEXT_PUBLIC_API_URL` pointant vers un backend
FastAPI **périmé/vide** (base sans cases → KPI à 0 ; version sans routes IA → 404). Les correctifs
rendent le frontend **résilient** à cet état (Cockpit cohérent, IA gracieuse). Pour une démo publique
irréprochable, choisir l'une des options :
1. **Redéployer/peupler le backend** (version courante + données démo) — restaure les outils IA réels.
2. **Retirer `NEXT_PUBLIC_API_URL`** du projet Vercel — la démo devient autonome (toutes les routes
   `/api/v1/*` à fallback démo) ; les outils IA affichent proprement « backend requis ». ⚠️ vérifier
   l'impact sur les intégrations « live » (Sirene, DECP) si elles dépendent du backend.
